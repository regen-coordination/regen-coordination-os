## 1. Decision summary

- **Driver:** Cost. Retire the ~$100/mo Discourse hosted custom-domain tier → **~$9–14/mo all-in** (≈85–90% cut; see §7 breakdown).
- **Target platform:** Hetzner Cloud, **CX32** (4 vCPU / 8 GB RAM / 80 GB NVMe, ~$7.69/mo). Chosen over CX22 so the ops owners never fight the 2 GB rebuild-OOM problem; over Hostinger because Hetzner is cheaper long-run (flat rate, no renewal shock) and exposes a full API/CLI for agent-driven lifecycle management.
- **Install:** Official `discourse_docker` launcher on Ubuntu 24.04. **No PaaS** (Railway/Fly rejected: Discourse only officially supports the Docker-on-VM path; PaaS is unsupported and, for a cost driver, more expensive and more fragile).
- **Ops owners post-migration:** Afo / Matty.
- **Agent execution model:** Agent drives provisioning + config + upkeep via **SSH key** (Discourse work) + **`hcloud` API token** (server lifecycle) + **Cloudflare API token** (DNS). Destructive/cutover steps (read-only freeze, DNS flip, plan cancellation) are **draft-and-present**, not autonomous.

### Verified current-state (admin API inventory, 2026-07-23)
- **Version:** `2026.7.0`. **Scale:** 187 users · 160 topics · 936 posts. Site total <200 MB.
- **Plugins (14, all official):** discourse-ai, chat, github, cakeday, reactions, narrative-bot, presence, local-dates, details, checklist, footnote, poll, spoiler-alert, lazy-videos. Only `discourse-lazy-videos` needs an explicit `app.yml` clone; the rest ship with core at this version.
- **Uploads:** on Discourse's managed CDN/S3 (`canada1.discourse-cdn.com/.../greenpill_hub/...`), **NOT local**. The self-serve backup is **DB-only** — the full backup *with uploads* is produced only by the **cancellation-triggered export** (Discourse support confirmed). Disk sizing is a non-issue (CX32 80 GB ≫ <200 MB).
- **SSO:** Discord login enabled (kept). **Email:** host-managed SMTP + inbound reply-by-email (self-host: own SMTP + disable inbound). `enforce_second_factor=staff`.

### Migration decisions (2026-07-23)
Keep **Discord** login (needs client secret) · **disable** discourse-ai (avoid LLM keys/cost during wind-down) · **disable** reply-by-email (inbound mail not replicated) · uploads via **cancellation export** (path A).

## 2. Architecture

Single Hetzner VM → one Docker container (the standard all-in-one: Postgres + Redis + Rails/Unicorn + nginx) → uploads on local NVMe → Let's Encrypt TLS → outbound mail via a **transactional SMTP provider** (required — see §5). DNS `A`/`AAAA` for `hub.regencoordination.xyz` points at the box (via Cloudflare — to confirm). The `latest.json` federation feed that the network reads comes free with any Discourse instance and is preserved unchanged.

```
Cloudflare DNS ──▶ Hetzner CX32 (Ubuntu 24.04)
                     └── Docker: Postgres · Redis · Rails · nginx
                           ├── uploads on local NVMe
                           ├── Let's Encrypt TLS
                           └── SMTP ──▶ transactional mail provider
```

## 3. Migration phases

### Phase 0 — Discovery, cancel, full backup
- **Inventory** ✅ done (version, plugins, SSO, scale — committed).
- **Get the full backup via cancellation.** Discourse support confirmed the self-serve backup is DB-only; the complete backup **with uploads** is generated by the **cancellation process** and made available to download (site <200 MB → ready in minutes). So: confirm authorization on the `greenpill_hub` (Greenpill-owned) account → **cancel** → download the cancellation backup (`.tar.gz`, DB + uploads). Cancelling does **not** take the site down early — it stays live until **July 30**, which is our rollback window.
- Procure secrets: `hcloud` token ✅, Cloudflare scoped DNS token, Discord client secret (to keep Discord login), SMTP credentials.

### Phase 1 — Provision (staging)
Create the Hetzner CX32 box (Ubuntu 24.04, SSH key, firewall 22/80/443). Point a **`hub-staging.regencoordination.xyz`** record at it so the full dry-run happens **without touching production**.

### Phase 2 — Install + restore on staging
Clone `discourse_docker`, run `./discourse-setup`, configure `app.yml` (staging hostname, SMTP, admin email, **matching plugin list**), bootstrap. Match Discourse version to source. Restore the backup, then **verify**: posts, users, uploads, categories, login, a real test email delivery, and `latest.json`.

### Phase 3 — Cutover (the only risky window)
1. Set the hosted forum **read-only**.
2. Take one **final fresh backup** (captures the last posts).
3. Restore that backup to the new box.
4. Switch hostname to production (`hub.regencoordination.xyz`) + rebuild.
5. Issue **Let's Encrypt TLS** (port 80 reachable; if Cloudflare proxy is on, disable proxy during issuance or use DNS challenge).
6. **Flip the Cloudflare DNS record** to the new IP (lower TTL a day ahead).
7. Verify end-to-end; re-enable Cloudflare proxy if used.

### Phase 4 — Stabilize + hand off
- **No separate cancellation step** — the plan is already cancelled and **auto-decommissions July 30**; the ~$92/mo saving is realized automatically. Complete cutover + this phase **before** July 30.
- Enable automated **daily backups** (Discourse built-in → Cloudflare R2) + Hetzner snapshots.
- Write the ops runbook: monthly `./launcher rebuild app`, restore drill, incident contacts (Afo / Matty).
- Update `federation.yaml` (note self-hosted), `TOOLS.md` (server IP / SSH), close the two HEARTBEAT tasks, correct the budget line (line 7, $250 placeholder → actual ~$10/mo).

## 4. Rollback / safety net

The hosted instance stays **fully alive until July 30** (end of the already-paid billing period). If cutover misbehaves before then, point DNS back to the hosted instance — near-zero data loss because the source is **read-only** during the switch. After July 30 the hosted site is gone, but the full backup is retained (zero data loss; only the live side-by-side fallback ends). **Therefore cutover must land before July 30.**
